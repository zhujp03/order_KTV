# order_system 本地测试用例（不含 Windows 打印）

> 用途：在开发机局域网中测试 UI 重构、订单业务和归档一致性。
>
> 本轮明确**不包含 Windows 打印工作端、打印任务领取、打印机连接、纸质小票和真实出纸**。因此本轮测试通过不代表打印链路已通过；打印兼容性必须另按[全量测试用例](14_FULL_TEST_USE_CASES.md)第 9 节在 Windows 与真实打印机环境验证。

---

## 1. 本地测试范围

### 1.1 包含

- 本机 Node 服务与 SQLite 的正常业务读写；
- 浏览器顾客扫码/点单页（可用手机或同一局域网浏览器）；
- Samsung Android 平板员工 App：登录、桌台、订单、菜品、合单/分单、结算、结单、只读历史；
- `admin_manage`：概览、菜单、桌台二维码、报表、员工；
- 二维码稳定性、Access Code 前端退役、订单归档与跨端数据一致性；
- 静态检查、Android 构建与本地 API 契约检查。

### 1.2 明确排除

- Windows 打印工作端的启动、登录、领取/完成打印任务；
- Windows Electron UI、系统打印机、静默打印、纸张、缺纸、离线、打印失败重试；
- “打印成功”“已出纸”“打印队列已被领取”的任何结论；
- AWS 域名、HTTPS、反向代理、真实生产数据和生产二维码。

### 1.3 本轮禁止事项

- 不直接修改 `database/` 里的 SQLite、WAL、SHM、JSON 文件；不执行手工 SQL、迁移、回填或清库。
- 不为测试改表、字段、SQL、归档逻辑、二维码 token 或 Access Code 兼容代码。
- 不把测试环境中的 UI 静态截图、Mock 数据或接口 200 当成完整通过。
- 不记录密码、完整 session、完整二维码 token 或个人顾客信息到测试报告。

## 2. 本地启动与设备准备

### 2.1 启动步骤

1. 在项目根目录安装依赖（首次或依赖有变更时）：`npm install`。
2. 按项目既有模板准备本地环境：`cp .env.local.example .env`。
3. 在 `.env` 中将 `PUBLIC_BASE_URL` 设为开发机的局域网 Wi-Fi 地址，例如 `http://192.168.x.x:3000`；不要使用 `127.0.0.1` 让平板或手机扫码。
4. 仅核对以下产品开关为 `false`，不要在报告中粘贴整个 `.env`：

   ```env
   ZONE_ACCESS_CODE_REQUIRED=false
   ROTATE_ACCESS_CODE_ON_CHECKOUT=false
   ```

5. 启动服务：`npm start`。
6. 用开发机打开 `http://127.0.0.1:3000/api/health`，再用平板/手机访问 `http://<局域网-IP>:3000/api/health`。
7. 确认开发机、Samsung 平板和至少一台顾客测试设备处于同一 Wi-Fi；关闭或放行本机防火墙对应端口。

使用管理页创建专用数据，名称示例：

## 3. 结果标记与通过条件

- `[ ] PASS`：结果符合预期，且附截图、录屏或脱敏接口证据。
- `[ ] FAIL`：记录实际结果、复现步骤、时间、设备和证据。
- `[ ] BLOCKED`：网络、权限、APK、设备等条件不足；不得写成通过。
- `[ ] N/A`：确实不适用本地环境，必须写明原因。

P0 失败即停止本轮验收；P1 失败需建立修复项；P2 可作为体验优化记录。所有“打印”结论在本轮只能填 `N/A（范围排除）`。
